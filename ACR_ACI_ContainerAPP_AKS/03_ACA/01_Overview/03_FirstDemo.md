# Demo: Create Your First Azure Container App

## 1. What We Are Going to Create

For this demo, we will create:

```text
Resource Group
│
├── Container Apps Environment
│      Name: con-env
│
└── Container App
       Name: con-app
```

Think of it as:

```text
Resource Group
      │
      ├── con-env
      │    Container Apps Environment
      │
      └── con-app
           Container App
```

The **Environment** is the boundary/platform where your Container Apps run.

The **Container App** is the actual application running inside that environment.

---

## 2. Portal Demo

Go to:

**Azure Portal → Create a resource → Container App**

On the **Basics** page:

### Subscription

Select your Azure subscription.

### Resource Group

Create or select your resource group.

For example:

```text
Resource Group: containerapp-rg
```

### Container App Name

Enter:

```text
con-app
```

### Region

Choose your preferred region.

For example:

```text
Central India
```

---

## 3. Container Apps Environment

During the creation process, Azure asks you for a **Container Apps Environment**.

Create a new environment:

```text
Environment name: con-env
```

So your configuration is:

```text
Container App
    con-app

Container Apps Environment
    con-env
```

After deployment, you should see **two resources** inside the resource group:

```text
containerapp-rg
│
├── con-env
│
└── con-app
```

> **Important Note:** `con-env` is the **Container Apps Environment**, while `con-app` is the **Container App**. Multiple Container Apps can run inside the same Container Apps Environment.

---

## 4. Quickstart

In the container configuration, Azure provides options for where your container image comes from.

Typically, you can work with sources such as:

```text
Quickstart
Azure Container Registry
Docker Hub
Other registry/image sources
```

For this demo, select:

> **Quickstart**

The purpose of this first demo is simply to create a Container App and access it from the Internet.

> **Important Note:** For this session, we are concentrating only on the **Quickstart** option. ACR and Docker Hub can be covered separately when we learn how to deploy our own container images.

---

## 5. Enable Ingress

For this demo, enable:

> **Ingress**

Choose:

```text
Ingress: Enabled
Traffic: External
```

This is important because we want to access the application from our browser.

Conceptually:

```text
Internet
    │
    ↓
Container Apps Ingress
    │
    ↓
con-app
    │
    ↓
Container
```

If you select **Internal**, the application isn't intended to be publicly accessible from the Internet.

---

## 6. Review + Create

Click:

**Review + create**

Then:

**Create**

Azure will create the environment and the Container App.

After deployment, go to:

```text
Resource Group
```

You should see something similar to:

```text
containerapp-rg

   con-env
   con-app
```

---

## 7. Open the Container App

Open:

**con-app**

On the Overview page, you'll find the application URL/FQDN.

It will look similar to:

```text
https://con-app.xxxxxxxx.centralindia.azurecontainerapps.io
```

The exact URL will be generated by Azure.

Click the URL.

Your browser should display the sample application.

The complete flow is:

```text
Browser
   │
   │ HTTPS
   ↓
Container App URL
   │
   ↓
Container Apps Ingress
   │
   ↓
con-app
   │
   ↓
Quickstart Container
```

> **Important Note:** The **FQDN/URL** is generated by Azure Container Apps when external ingress is enabled. You can use this URL directly from a browser to access your application.

# 8. Azure CLI — Create Container App

You can also create the same type of application using Azure CLI.

## Bash / Linux

First set the variables:

```bash
RG="containerapp-rg"
LOCATION="centralindia"
ENV="con-env"
APP="con-app"
```

Create the resource group:

```bash
az group create \
  --name $RG \
  --location $LOCATION
```

Create the Container Apps Environment:

```bash
az containerapp env create \
  --name $ENV \
  --resource-group $RG \
  --location $LOCATION
```

Now create the Container App:

```bash
az containerapp create \
  --name $APP \
  --resource-group $RG \
  --environment $ENV \
  --image mcr.microsoft.com/k8se/quickstart:latest \
  --target-port 80 \
  --ingress external
```

The important parameters are:

```text
--name
    con-app

--environment
    con-env

--image
    Quickstart container image

--target-port
    80

--ingress external
    Make the application publicly accessible
```

---

# 9. Get the Application URL Using CLI

After creating the Container App:

```bash
az containerapp show \
  --name $APP \
  --resource-group $RG \
  --query properties.configuration.ingress.fqdn \
  --output tsv
```

You'll get something similar to:

```text
con-app.xxxxxxxx.centralindia.azurecontainerapps.io
```

Then open:

```text
https://con-app.xxxxxxxx.centralindia.azurecontainerapps.io
```

# 11. Final Architecture

```text
                    Azure
                      │
               Resource Group
                      │
             ┌────────┴────────┐
             │                 │
          con-env            con-app
        Environment       Container App
             │                 │
             │                 │
             └───────┬─────────┘
                     │
              Quickstart Image
                     │
                     ↓
              Container Instance
                     │
                     ↓
              External Ingress
                     │
                     ↓
                  Internet
                     │
                     ↓
               Browser / URL
```

## Key Points to Remember

**Environment** → Where Container Apps run.

**Container App** → The actual application/workload.

**Quickstart** → Azure-provided sample container image for getting started quickly.

**Ingress** → Controls how traffic reaches the Container App.

**External Ingress** → Makes the application accessible from the Internet.

**FQDN** → The URL generated by Azure that you can use to access the Container App.
