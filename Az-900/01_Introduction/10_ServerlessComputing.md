
# AZ-900: Serverless Computing

## 1. Introduction

Serverless computing is a cloud computing model in which the cloud provider manages the underlying infrastructure, including server provisioning, infrastructure maintenance, and much of the scaling.

Developers can focus on writing and deploying code or building applications instead of managing servers.

**Important:** Serverless does not mean that servers do not exist. Servers are still used, but the cloud provider manages them.

In Microsoft Azure, common serverless services include:

- Azure Functions
- Azure Logic Apps
- Azure Event Grid
- Azure Container Apps (which supports serverless container scenarios)
- Azure serverless options for data storage and application hosting

---

## 2. What Is Serverless Computing?

In a traditional application deployment, an organization may need to:

1. Provision virtual machines.
2. Install and configure an operating system.
3. Install required software and runtime environments.
4. Configure scaling and availability.
5. Apply operating system patches.
6. Monitor and maintain the infrastructure.

With serverless computing, the cloud provider manages much of the underlying infrastructure.

Developers focus on the application code, business logic, or workflows.

### Example Scenario

Suppose an e-commerce company wants to send an email whenever a customer places an order.

Without serverless computing, the company might run an application on a virtual machine that continuously checks for new orders.

With a serverless approach, an Azure Function can execute when an order event triggers it. The function processes the order event and sends a notification.

The company does not need to manage a dedicated virtual machine for that function.

---

## 3. How Serverless Computing Works

A typical event-driven serverless application follows these steps:

1. An event occurs.
2. The event triggers a serverless function or workflow.
3. The function executes the required business logic.
4. The application interacts with other services if needed.
5. The execution completes, and the platform manages the underlying infrastructure.

### Example: Image Processing

Imagine a company allows users to upload profile pictures to Azure Storage.

The workflow could be:

1. A user uploads an image.
2. The upload generates an event.
3. An Azure Function is triggered.
4. The function resizes the image.
5. The processed image is saved to storage.

The function executes when required, rather than relying on a developer-managed server that continuously polls for new images.

---

## 4. Characteristics of Serverless Computing

### 4.1 No Server Management

The cloud provider manages the underlying servers and infrastructure.

Developers generally do not need to provision or maintain the servers that execute their functions.

### 4.2 Automatic Scaling

Serverless platforms can scale execution capacity based on workload and platform configuration.

For example, if an application receives many requests, the platform may run additional function instances to handle the workload.

Scaling limits and behavior depend on the service, hosting plan, region, and configuration.

### 4.3 Event-Driven Execution

Many serverless applications execute in response to events.

Examples include:

- An HTTP request
- A file uploaded to storage
- A message arriving in a queue
- A scheduled timer
- An event generated by another application

### 4.4 Consumption-Based Pricing

Many serverless services offer consumption-based pricing.

Depending on the service and pricing plan, charges may depend on factors such as:

- Number of executions
- Execution duration
- Memory or compute resources used
- Requests processed
- Data stored or transferred
- Related services consumed

**Important:** Serverless does not always mean zero cost when the application is idle. Some plans and supporting resources may incur charges even when no function is executing.

---

## 5. Traditional Computing vs. Serverless Computing

| Feature | Traditional VM-Based Computing | Serverless Computing |
|---|---|---|
| Infrastructure management | Customer manages the VM and operating system | Cloud provider manages the underlying execution infrastructure |
| Server provisioning | Usually required | Usually not required by the developer |
| Scaling | Must be configured and managed | Often handled automatically by the platform |
| Execution | Applications may run continuously | Many workloads execute in response to events |
| Pricing | Often includes allocated compute capacity over time | Often based on executions and resource consumption |
| Maintenance | Customer manages guest OS patches and configuration | Provider manages the underlying server infrastructure |
| Best suited for | Long-running applications and workloads needing OS control | Event-driven tasks, APIs, automation, and intermittent workloads |

The exact responsibilities and pricing depend on the chosen service and plan.

## 6. Azure Functions

Azure Functions is an event-driven serverless compute service that executes code in response to triggers.

Developers can write functions using supported programming languages and integrate them with other Azure services.

### Common Azure Functions Triggers

| Trigger | Example |
|---|---|
| HTTP trigger | Execute a function when an HTTP request arrives |
| Timer trigger | Run a scheduled task |
| Blob Storage trigger | Process a file uploaded to storage |
| Queue trigger | Process messages from a queue |
| Event Grid trigger | React to events from supported sources |

The available triggers and supported features depend on the Functions runtime, language, extension, and hosting plan.

### Example Use Cases

- Process uploaded files.
- Send email notifications.
- Execute scheduled cleanup tasks.
- Process queue messages.
- Build lightweight HTTP APIs.
- Automate background tasks.

### Example Scenario

A company receives thousands of invoices every day.

Whenever a new invoice is uploaded to Azure Blob Storage, an Azure Function can be triggered to validate the file and extract relevant information.

The company can use serverless execution to avoid managing a dedicated server just for this event-driven processing task.

---

## 7. Azure Logic Apps

Azure Logic Apps is a cloud service for creating automated workflows and integrating applications, data, and services.

It provides a visual designer, triggers, and connectors to build workflows with limited code.

### Example Workflow

A company wants to automate an approval process.

1. An employee submits a request.
2. A workflow starts.
3. An approval request is sent to a manager.
4. The manager approves or rejects the request.
5. The workflow sends a notification and updates another system.

Azure Logic Apps can coordinate these steps using connectors and workflow actions.

### Common Use Cases

- Business process automation
- Approval workflows
- Email notifications
- Application integration
- Scheduled data processing
- Connecting cloud services and on-premises systems through supported connectors and configurations

**AZ-900 exam tip:** Azure Functions is primarily used to execute code, while Azure Logic Apps is primarily used to orchestrate workflows and integrate services.

---

## 8. Azure Functions vs. Azure Logic Apps

| Feature | Azure Functions | Azure Logic Apps |
|---|---|---|
| Primary purpose | Run application code | Automate and orchestrate workflows |
| Development approach | Write code | Visual designer and workflow definitions |
| Typical users | Developers | Developers, integration specialists, and business automation teams |
| Common example | Process an uploaded image | Send an approval request and update a business system |
| Event-driven | Yes | Yes |
| Integration | Through code, bindings, and supported integrations | Through triggers, actions, and connectors |

Both services can work together in the same solution.

For example, Logic Apps can coordinate a business workflow and call an Azure Function to perform custom data processing.

---

## 9. Serverless Computing and Containers

Serverless computing can also be used with containers.

Azure Container Apps supports serverless-style container hosting, including scaling based on HTTP traffic or supported event sources.

This allows developers to deploy containerized applications without managing the underlying Kubernetes infrastructure directly.

### Example

A company packages a web API into a Docker container and deploys it to Azure Container Apps.

The application can scale based on configured rules, and some configurations can scale down to zero replicas.

The exact behavior depends on the application configuration and scaling rules.

### Important Distinction

- Azure Functions: Best known for event-driven function execution.
- Azure Container Apps: Runs containerized applications and supports serverless-style scaling.
- Azure Virtual Machines: Provides more direct control over the operating system and virtual machine environment.
- Azure Kubernetes Service (AKS): Managed Kubernetes for container orchestration, where customers still manage aspects of cluster configuration and operations.

---

## 10. Serverless Computing vs. PaaS

Serverless computing is closely related to Platform as a Service (PaaS), but the terms are not identical.

PaaS provides a managed application platform so developers can build and deploy applications without managing the underlying physical infrastructure.

Serverless emphasizes abstracting infrastructure management and, in many cases, scaling execution according to demand and charging based on consumption.

| Feature | PaaS | Serverless |
|---|---|---|
| Infrastructure management | Provider manages underlying infrastructure | Provider manages underlying execution infrastructure |
| Application deployment | Deploy an application to a managed platform | Deploy functions, workflows, or supported applications |
| Scaling | May require configuration and may use fixed capacity | Often automatically scales based on demand or events |
| Pricing | May charge for allocated resources or plan capacity | Often uses execution- or consumption-based pricing |
| Example | Azure App Service | Azure Functions |

These categories can overlap. For example, Azure Functions is a serverless service, and Azure App Service is a PaaS offering.

## 11. Advantages of Serverless Computing

### 11.1 Reduced Infrastructure Management

Developers spend less time provisioning and maintaining servers.

### 11.2 Automatic Scaling

The platform can adjust execution capacity according to supported scaling rules.

### 11.3 Faster Development

Developers can focus on application logic rather than infrastructure setup.

### 11.4 Potential Cost Savings

For intermittent workloads, consumption-based billing may reduce costs compared with maintaining dedicated compute capacity continuously.

Savings depend on actual usage, pricing plans, execution duration, and related services.

### 11.5 Event-Driven Architecture

Serverless services integrate well with events, queues, storage, APIs, and automated workflows.

---

## 12. Limitations of Serverless Computing

Serverless computing also has limitations.

- **Execution limits:** Some plans impose maximum execution durations or other resource limits.
- **Cold starts:** Some configurations may experience startup latency when new instances are initialized.
- **Limited infrastructure control:** Developers have less direct control over the underlying operating system and runtime environment.
- **Vendor-specific integrations:** Applications may depend on provider-specific services and APIs.
- **Cost unpredictability:** High request volumes or inefficient execution can increase costs.
- **Debugging and monitoring:** Distributed, event-driven applications may require additional monitoring and tracing.

The exact limitations depend on the selected Azure service and hosting plan.

## 13. Practical Azure Example: Serverless Order Notification

### Requirement

An online store wants to send a notification whenever a new order is received.

### Proposed Architecture

1. A customer places an order through the online store.
2. The order is stored in a database or published as a message.
3. An event or message triggers an Azure Function.
4. The function processes the order information.
5. The function calls a supported notification service or API.
6. The notification is sent to the customer.

### Benefits

- No dedicated VM is required just to execute the notification function.
- The function can scale according to the configured hosting plan.
- The application can respond to events.
- Consumption-based pricing may be suitable when order traffic varies.

### Important Consideration

The database, messaging service, notification provider, and other supporting resources may have separate costs and configuration requirements.

---

## 14. When Should You Use Serverless Computing?

Serverless is a good option when:

- The application is triggered by events.
- Workloads are intermittent or unpredictable.
- You want to reduce infrastructure management.
- You need lightweight APIs or background processing.
- You want to automate workflows between services.
- You prefer to focus on code or business logic.

A VM or another hosting model may be more appropriate when you need extensive operating system control, specialized software, or a workload that fits better with continuously allocated compute capacity.
